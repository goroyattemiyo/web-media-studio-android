## Product direction

WMS Android is the main mobile implementation for:

`Share URL -> local acquisition -> Local Library -> Playlist -> background / screen-off playback`

The app is development-distributed only for now; Play Store publication is not a requirement.

Supported-source ambition is broader than YouTube: public URLs such as YouTube, TikTok, Instagram Reels and other yt-dlp-compatible sites, subject to rights/permission checks and without DRM/auth bypass.

## Gate A0 goal

Prove the smallest real-device path:

`URL input/share -> Probe -> save MP3 locally -> Media3 playback`

Library, playlist, background playback and polished UI come only after A0 succeeds.

## Current implementation

- Kotlin + Jetpack Compose
- Media3 / ExoPlayer local preview
- `youtubedl-android` + FFmpeg acquisition engine
- `MediaAcquisitionEngine` abstraction to allow engine replacement later

### YouTube acquisition diagnostic

On a short public YouTube video, Probe succeeded but `Save audio / MP3 192 kbps` returned:

`ERROR SOURCE_FORBIDDEN`

UI message:

`配信元から取得が拒否されました。現在の取得方式ではこのメディアを保存できません。`

Important: this means the failure is not simply `OUTPUT_NOT_FOUND` and not currently proven to be `JS_RUNTIME_REQUIRED`. The real download request is being rejected/forbidden somewhere in the current acquisition path. Do not claim the JS-runtime hypothesis is confirmed.

### TikTok diagnostic

A public TikTok URL failed Probe with:

`ERROR PROBE_FAILED`

Diagnostic text exposed:

`WARNING: Your yt-dlp version (2025.11.12) is older than 90 days!`

This is a major current clue: the APK's active yt-dlp is stale relative to the current date (2026-09-11).

## Important upstream facts already checked

- Current dependency in WMS Android: `io.github.junkfood02.youtubedl-android:library:0.18.1` + FFmpeg `0.18.1`.
- The upstream youtubedl-android API supports runtime yt-dlp update via `YoutubeDL.getInstance().updateYoutubeDL(appContext, UpdateChannel.STABLE)`.
- WMS Gate A0 intentionally did **not** call `updateYoutubeDL()` yet because packaged runtime compatibility was being proven first.
- Probe working proves the packaged Python/yt-dlp runtime can execute at least metadata extraction.
- Do not introduce cookie/login/DRM bypasses. Public/authorized media only.

## Recommended next step

Before adding QuickJS/Deno or replacing the engine, test the simplest current hypothesis first: **update yt-dlp to current stable inside the Android app, then retest the exact same YouTube and TikTok URLs.**

Suggested implementation sequence:

1. Add controlled yt-dlp update support to Gate A0 using upstream `updateYoutubeDL(..., STABLE)`.
2. Show active yt-dlp version in the Gate A0 diagnostic UI before/after update.
3. Prefer a clear `Update yt-dlp` action or safe one-time startup update for the spike; do not hide failures.
4. Keep the bundled version as fallback if update fails.
5. Rebuild APK through CI.
6. Retest the same YouTube short URL:
   - Probe
   - rights confirmation
   - MP3 acquisition
   - Media3 playback
7. Retest the same TikTok URL Probe/acquisition.
8. Only if current stable yt-dlp still reports JS-runtime/EJS-specific errors should Gate A0 move to an Android JS-runtime integration (QuickJS is the lightweight first candidate).
